## Auto-Healing and Scaling Applications

### Overview

In this project, I explored application resilience and elasticity by analyzing the auto-healing and scaling capabilities of Auto Scaling groups. I configured scaling boundaries, implemented automated scaling strategies, and designed solutions that respond dynamically to both scheduled events and performance-based demand changes.

---

### Services I Worked With

* **Amazon EC2 Auto Scaling** — Automatically adjusts EC2 capacity to maintain application performance while optimizing costs
* **Amazon CloudWatch** — Monitors system metrics and triggers scaling actions based on configured thresholds
* **Amazon Elastic Compute Cloud (EC2)** — Compute instances managed within Auto Scaling groups for automated capacity control

---

###  What I Demonstrated

Through this SimuLearn exercise, I demonstrated an understanding of:

* Auto-healing capabilities in Auto Scaling groups, including health checks and automatic instance replacement
* Dynamic scaling methods used to adapt to changing application workloads
* Configuring Auto Scaling groups with minimum, maximum, and desired capacity settings
* Implementing scaling boundaries to balance resource availability and cost control
* Creating and configuring scaling policies driven by performance metrics
* Using time-based scaling strategies for predictable traffic patterns
* Monitoring application performance with CloudWatch metrics and alarms
* Configuring launch templates for consistent EC2 deployments within Auto Scaling groups
* Designing highly available architectures using multi-Availability Zone Auto Scaling deployments
