## Core Security Concepts
### Overview

In this exercise, I explored the fundamentals of AWS security by comparing IAM identity models, analyzing policy structures, understanding the AWS Shared Responsibility Model, and applying security best practices to manage secure access to AWS resources.

### Services I Worked With

AWS Identity and Access Management (IAM) — Used to manage users, roles, groups, and permissions for secure and controlled access to AWS resources

Amazon Elastic Compute Cloud (EC2) — Configured with IAM roles to enable secure access between AWS services

Amazon Relational Database Service (RDS) — Secured using IAM authentication methods and access control policies



### What I Demonstrated
Through this SimuLearn exercise, I demonstrated an understanding of:


* IAM identity types such as users, roles, and groups, including how to create and manage them

* The differences and practical use cases for users, roles, and groups in access management

* IAM policy structure, including principals, actions, resources, and conditions

* Permission evaluation logic and the use of permission boundaries

* The AWS Shared Responsibility Model and how security responsibilities are divided between AWS and customers

* AWS compliance programs and their importance for organizational security and regulatory requirements

* IAM best practices, including least privilege access and secure identity management

* Role-based access control for applications and service-to-service communication

* The security impact of identity and access management decisions within cloud environments
